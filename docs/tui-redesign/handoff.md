# Handoff — TuiRedesign

One block per shipped ticket, appended by the builder before the review gate runs. Pointers into the diff, not a narrative. Read the index first (`bash scripts/docs-slice.sh index handoff`), then slice only the ids you need.

### s1-cell-rendertablefit (a0bcb37)

meant: aligned columns that survive a long value, spec.md:10.
did: `ui/utils/utils.go` — `Cell{Text, Color}` with `Cell.render`, `RenderTableFit`, `fitColumnWidths`. Weight 0 sizes to widest cell, weight >0 shares the remaining budget, last flexible column takes the rounding remainder so the table fills the width exactly. `RenderTable` untouched.
deviations: `Cell.Color` is a `color.Attribute`, not a `*color.Color` — an Attribute is what `utils.ColoredString` takes, so the precomputed-escape path is kept and no Color is allocated per cell; the zero value therefore has to mean "unstyled" (`color.Reset` as a cell style is meaningless) and is documented on the field. Validation is wider than the ticket asked: also errors on a weights slice that does not match the column count, and on a negative weight, because both would silently mis-lay-out every row. Degenerate case the ticket did not specify — when content-sized columns alone overrun the terminal, the budget is spent left to right and the trailing columns are squeezed to zero; chosen because the leftmost columns carry the identifying text. No benchmark: `s9-benchmarks` owns it.
verified: `make lint`, `make test` (both exit 0). Exact-string tests in `ui/utils/utils_test.go` (`TestRenderTableFit*`), plus `TestRenderTableFitNeverExceedsTheWidth` sweeping every width 0-45 across each weight shape, wide runes and colour. Green covers the width arithmetic, the CJK cut, the remainder, and that escapes wrap the truncated text; it does not cover anything on screen, since nothing calls this yet.
threads: `runewidth.Truncate` subtracts the tail's width from the budget, so at width 0 it returns a one-cell `…` and overruns the column — `Cell.render` guards width <= 0 for that reason, do not remove it. Cell.Text must be plain: passing pre-coloured text defeats the whole design and mismeasures the column.

### s1-primitives (8c9f314)

meant: semantic status badges, icon plus word, never colour alone, spec.md:10.
did: `ui/presentation/primitives.go` — `Badge`, `Gauge`, `RelTime` (+ `compactDuration`), `SectionTitle`, `ResourceHeader`, `FormatByteCount`. `ui/presentation/status.go` gains `statusKindOf`, now shared with `StatusCell`. `ui/ec2_panel.go:267` `formatByteCount` is a one-line alias over `presentation.FormatByteCount`.
deviations: `Badge` uses the icon from `statusStyleTable` (`▶ ⨯ ⟳ − !`), so it does NOT render the `●` the mockups show — the ticket says "through the existing statusStyleTable aliases" and that is the table's icon. A later ticket wanting `●` changes the table, not Badge. Three guards the ticket did not ask for, each preventing a real failure rather than adding scope: `Gauge` clamps NaN (a CloudWatch metric with no datapoints arrives NaN, NaN-to-int is undefined in Go, the bar length goes negative and `strings.Repeat` panics), `RelTime` reports the zero value as `unknown` (an absent AWS timestamp would otherwise be related against year 1) and renders future times as `in 7d` (rotation dates are in the future; without it the output is a negative duration). Small refactor outside the three new files: `statusKindOf` extracted from `StatusCell` so Badge cannot drift from it — the alternative was duplicating the alias lookup. `FormatByteCount` moved verbatim, including its unbounded `"KMGTPE"[exp]` index; not touched, so the move changes no behaviour.
verified: `make lint`, `make test` (both exit 0). Exact-string tests per primitive in `primitives_test.go`, colour asserted under a local `forceColor` helper. `ui/ec2_panel_test.go` still exercises the alias unchanged, which is what proves the move was behaviour-preserving.
threads: `color.Faint` (the muted attribute, used by `ResourceHeader` and wanted by `s2-inpanel-empty`) is NOT in `utils.colorWraps`, so it takes the un-precomputed fallback. Correct output, one allocation per call; left alone because nothing measures it yet. `ResourceHeader` always emits three lines, even with no meta, so sections below it do not shift — a caller that trims the trailing newline breaks that.

### s1-columns (50e891f)

meant: two-column overviews that collapse to one column on narrow terminals and never soft-wrap, spec.md:12.
did: `ui/presentation/columns.go` — `Columns`, `truncateStyled`, `csiPrefixLen`, `minTwoColWidth = 110`. Splits both blocks on newlines, cuts each line to `(width - 2*gap - 1) / 2`, pads the left with `utils.WithPadding`, joins with a `│` rule; stacks below the threshold.
deviations: the ticket says "ANSI-aware measurement via Decolorise", which taken literally means decolorising before the cut and losing the line's colour exactly when it overflows. Implemented as escape-preserving truncation instead (`truncateStyled` copies CSI sequences through, counts only visible cells, closes the cut with a reset) — measurement is still Decolorise-based, the colour just survives. `gap` is defined as the blank cells on EACH side of the rule, so the rule consumes `2*gap + 1`; the ticket did not say which. Two policies it did not specify: an empty right block returns the left block untouched, and a gap wide enough to leave no column falls back to stacked instead of emitting negative padding. Width is counted per rune, not per grapheme cluster, so a combining mark would be double-counted — noted in the comment, no AWS identifier carries one. No benchmark: `s9-benchmarks` owns it.
verified: `make lint`, `make test` (both exit 0). `columns_test.go` covers ragged heights, coloured measurement, the narrow fallback and the threshold itself, empty blocks, plain and coloured truncation, plus `truncateStyled`/`csiPrefixLen` directly, and `TestColumnsNeverExceedsTheWidth` sweeps every width up to 260 across four gaps. Green proves the string arithmetic; it proves nothing about how 110 looks on a real terminal.
threads: `minTwoColWidth = 110` is a starting guess to be tuned by eye, so the tests deliberately use width 200 and only the threshold test references the constant — tuning it must not rewrite every expectation. `csiPrefixLen` handles CSI only, matching what `utils.Decolorise`'s regexp matches and what fatih/color emits; an OSC sequence would be counted as text.

### s2-inpanel-empty (21c5126)

meant: in-panel empty states, spec.md:10.
did: `ui/panels/side_list_panel.go` — `emptyMessage`, `afterRerender`; `RerenderList` branches on an empty list before building a table. The eight panels' `NoItemsMessage` values lose their trailing "found".
deviations: profiles reads `no AWS profiles in ~/.aws/config`, not the ticket's bare style — the path is the only actionable thing the message says, and with no profiles there is no row to select to reach the Config tab that would otherwise tell you. `emptyMessage` is a method rather than an inline `ColoredString` call purely so the muting is testable; gocui parses escapes into cell attributes, so `View.Buffer()` returns the text stripped and no view assertion can see `color.Faint`. `afterRerender` is an extraction, not new behaviour: the empty branch owes `OnRerender` and the focused-view `HandleSelect` exactly what the table branch owes them.
verified: `make lint`, `make test` (both exit 0). `ui/eks_panel_test.go` headless: the message reaches the EKS view buffer, and disappears once a cluster is listed. `ui/panels/side_list_panel_test.go` pure: the muting, and the menu panel's empty message staying empty rather than becoming a bare escape pair. Four mutants (empty branch removed, message unmuted, blank-message guard dropped, message shown alongside rows) each failed a test.
threads: the blank-message test only bites under `forceColor` — a test binary is not a tty, so without it `ColoredString` returns plain and the guard's mutant survives. That is why `forceColor` now exists in `ui/panels` too.

### s2-left-profiles-ecs (a1c3d7f)

meant: aligned columns and semantic status badges on the left panels, spec.md:10.
did: `ui/panels/side_list_panel.go` — `GetTableCellsFit`, `Weights`, `renderTable`, `searchCells`. `ui/presentation/status.go` — `StatusCellFit`, `GetProfileDisplayCells`. `ui/presentation/ecs.go` — `GetECSClusterDisplayCells` (+ `ecsClusterBadge`), service and task cell rows, three weight functions. `ui/utils/utils.go` — `Cell.Rendered`.
deviations: the ticket scopes the ECS work to cluster rows, but services and tasks had to move too — one panel has one render path, and `RenderTableFit` rejects ragged rows. Those two are a mechanical 1:1 conversion, same content and colours; only clusters gain the badge. `Weights` is `func(T) []int` rather than a slice because the ECS panel is three tables depending on drill level; taking the first row means the weights always describe the rows actually being rendered, where reading `gui.ecsDrill` could describe a level a queued rerender has already left. The badge reads `● healthy` / `● deploying` / `● <status>`, not `Badge()` from s1-primitives, which renders the `statusStyleTable` icon and the raw status word — the ticket specifies this text. Only an ACTIVE cluster is ever `deploying`; the ticket's literal ordering would call a cluster that is being deleted with tasks still draining "deploying", which reads as progress. An absent status renders `● unknown` rather than a bare `● `. Filtering changed behaviour: it now matches `Cell.Text`, where before it matched rendered strings carrying colour escapes, so a filter could not hit a coloured column. `GetECSServiceDisplayStrings` survives as a thin `Rendered()` projection because the cluster inspector's services table still uses `RenderTable`; its pre-existing test passes unchanged, which is what shows the conversion preserved behaviour.
verified: `make lint`, `make test` (both exit 0). Exact-cell tests per cluster state in `ui/presentation/ecs_test.go` including empty/INACTIVE/DEPROVISIONING/absent-status, profiles in `status_test.go`, filter and `SelectByCell` over a migrated panel in `ui/panels/side_list_panel_test.go`, and a headless `TestECSPanelRendersClusterRowsInsideTheViewWidth` that resizes the ECS view to 60 and asserts no rendered line exceeds it. 11 mutants killed. Green does not cover how any of it looks on a real terminal.
threads: `Cell.Rendered` exists because `ColoredString(text, 0)` wraps text in a reset pair — the zero attribute means unstyled to `Cell` and `color.Reset` to fatih/color. That bug was live in the first draft of the services-table conversion and the test caught it; every string-form conversion must go through `Rendered`, never `ColoredString(cell.Text, cell.Color)`. The headless harness leaves views at the 10-cell placeholder `createAllViews` sets (`InnerWidth()` = 8), so any view-level row assertion has to resize first — `resizeView` in `ui/ecs_panel_test.go` does it and restores the size on cleanup, which matters because the gocui screen is one process-wide global.

### s2-left-ec2-s3 (d30c315)

meant: prominent name, muted identifiers, aligned columns, spec.md:10.
did: `ui/presentation/ec2.go` — `GetInstanceDisplayCells`, `InstanceWeights`. `ui/presentation/s3.go` — `GetBucketDisplayCells`, `BucketWeights`. Both panels switched to `GetTableCellsFit`.
deviations: the instance id column is flexible (weight 1 against the name's 2), where the ticket implies only the name flexes. The ticket's own mandated case — a 60-char name at width 40 — is what forced it: icon, id, type and private IP are 36 cells of content plus 4 separators, so the flexible name column resolved to zero width and the name vanished while four narrower columns survived. Both text columns now share the squeeze. The status icon stays as the first cell; the ticket lists four fields but removing the icon would drop information, which spec.md:11 forbids.
verified: `make lint`, `make test` (both exit 0). `ui/presentation/ec2_test.go` and `s3_test.go`: exact cells named and unnamed, the 60-char name at width 40 asserting total width, the ellipsis, the name surviving and the other columns still readable, that colour is applied after the cut, and that each weight table matches its row width. 7 mutants killed.
threads: the same narrow-width squeeze applies to the ECS cluster row, whose five columns are ~44 cells of content — see the review line for what was done about it.

### Group notes (s2-inpanel-empty, s2-left-profiles-ecs, s2-left-ec2-s3)

Not delegated. The bulk here looked mechanical — four panels, one conversion each — but it was not specifiable in advance: the shared `GetTableCellsFit`/`Weights` seam had to be designed against the ECS panel's shifting row shape before any panel could move, and the weight tables were decided by measuring rendered rows across widths 30-100, not by a rule anyone could have written into a plan. The one genuinely mechanical part, converting the string formatters to cells, is under a hundred lines; a router plan precise enough to hand it down would have cost more than it saved.

Connected AWS verification: not run. Nothing here depends on a response shape — every change is downstream of structs the repo already populates — and the surfaces worth eyeballing (a narrow panel, an empty panel, a badge) are exercised by the width sweeps and the headless view tests instead. No profile was used and no AWS call was made, so the "how does it actually look at 40 cells" question is answered by measurement, not by sight; `s10-ui-journeys-panels` is where that gets seen.
