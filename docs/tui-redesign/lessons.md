# Lessons — TuiRedesign

Durable lessons only: a gate invocation that works here, a repo gotcha, a class of ticket that keeps failing and why. Read every cycle, so keep it tight.

- Gate is `make lint` then `make test` from the repo root, both exit 0 on a clean tree; `make bench` covers only `./ui/ ./ui/resources/ ./ui/fuzzy/`, so a benchmark added under `ui/utils` or `ui/presentation` will not run until that target's package list grows.
- For width/truncation code, an exact-string test pins one width and proves little about the arithmetic. Pair it with a sweep over every width (plus wide runes and colour) asserting the visible width never exceeds the budget. It found no live bug in stage 1, but mutation-testing showed it kills the whole off-by-one class the per-case expectations sail past: a dropped budget clamp, a forgotten column separator, a forgotten rule cell, a forgotten ellipsis cell.
- Audit a diff by mutation, not by re-reading it. Break one invariant, run the one test that should fail, revert. A surviving mutant is a test that asserts nothing, and it is the cheapest way to tell a real assertion from a plausible-looking one.
- `runewidth.Truncate(s, w, tail)` subtracts the tail's width from `w` and returns just the tail when nothing fits, so at `w == 0` it emits a one-cell `…` and overruns the column. Guard `width <= 0` before calling it.
- Verify a test's own arithmetic against the code, not the reverse: `\x1b[1;32m` is 7 bytes, and a hand-computed 8 sent the first red gate. When a single new assertion fails, suspect the expectation before the implementation.
- Colour and truncation do not commute. Truncate plain text and colour the result; cutting an already-coloured string splits an escape pair and bleeds into the next column. Where a pre-rendered line must be cut (`presentation.truncateStyled`), copy CSI sequences through untouched, count only visible cells, and close the cut with a reset.
- `RenderTableFit` pays content-sized columns in full before flexible ones, so a row whose content columns fill the panel renders with its flexible column empty — the identifying text is the first thing lost, and it is silent. Check every new row shape at the width it will really get (a side panel is 30-60 cells, not 120), and remember that widening the name's weight is not a fix: a flexible column's share ignores its content, so it over-truncates its neighbour at wide widths. `flexibleFloor` handles the general case; a new row shape still needs its own narrow-width test.
- Headless views sit at the 10-cell placeholder `createAllViews` sets (`InnerWidth()` = 8), so any assertion about rendered row content must resize the view first (`resizeView` in `ui/ecs_panel_test.go`) and restore it, since the gocui screen is one process-wide global. gocui also parses escapes into cell attributes, so `View.Buffer()` never shows colour — assert styling on the string the code writes, not on the view.
- `utils.ColoredString(text, 0)` emits `\x1b[0mtext\x1b[0m`: attribute 0 is `color.Reset`, while a `Cell`'s zero Color means unstyled. Convert cells to strings with `Cell.Rendered()`, never by calling `ColoredString(cell.Text, cell.Color)`.
- Give a column a weight ONLY when its content has no natural width. A fixed-width value on a flexible weight (an AWS id, a timestamp) is under-paid at wide widths and truncated while its neighbour pads: seen on the vpc id, cut at width 60 with 28 idle cells beside it. Content-size it and let one text column take the slack; `flexibleFloor` already protects that column when the panel is narrow. Print the rows at 30/40/50/60 and read them before choosing — both stage-2 weight bugs were invisible in the exact-cell tests and obvious in the output.
- A `Contains` assertion cannot see a truncation, because the cut string still contains the prefix it was asked about. Assert the boundary instead (`HasSuffix`, total width, or the row ending where it should), or the mutant that removes the trimming survives.
- Migrating a panel to `GetTableCellsFit` deletes whatever placeholder branches its old string formatter had (`if status == "" { status = "-" }`). Each one is a behaviour change with no test unless you write it: grep the old formatter for its empty/default cases before deleting it.
- Dead end, do not re-derive: `View.SelFgColor` cannot restyle a selected row on the pinned gocui. `setRune`'s `Highlight` branch forces the bright fg variant plus `AttrBold` and ORs `SelBgColor`, never reading `SelFgColor` (which only reaches tab titles, and side panels have no tabs). Measured `fg=default bg=navy bold=true` with `SelFgColor = ColorRed`. Selection styling is `SelBgColor` and nothing else until gocui is bumped.
- A test that calls a panel method with its own inline closure does not test the panel's WIRING: mutating a loader's key from the instance id to the name tag left the suite green. Where a call site passes a closure that encodes a decision, name it and have the test reference the same symbol, or the decision is untested however many tests surround it.
- To assert what was actually DRAWN (colour, attributes), read the tcell simulation screen: headless gocui sets the package-global `gocui.Screen` to a `tcell.SimulationScreen`, and `GetContents()` gives cells with styles. `View.Buffer()` cannot see this — gocui has already parsed the escapes into cell attributes. Costs a direct `gdamore/tcell` import, so use it to answer a question, not as a routine assertion.
- A panel's tab index outlives its tab set. `ContextState.mainTabIdx` is held while `GetMainTabs()` can return a shorter list (the ECS drill levels), and only `drillECS` reset it — `resetDependentPanelState` did not, which was an index-out-of-range crash on a profile switch. `GetCurrentMainTab` now clamps, so adding or removing a tab is safe again, but the general lesson is that any index kept beside a list that a closure regenerates needs the clamp at the READ, not at each writer.
- A config key is published twice: `DefaultUserConfig` and the sample block in `README.md`. Nothing pins them to each other (`TestReadmeKeyTableIsCurrent` covers only the keybindings table), so a new key silently leaves the documented sample incomplete. Add it to both in the same commit.
- The mutation harness must run EVERY package the mutant can reach. A first pass scored `ui/panels` mutants against `go test ./ui/ ./config/` and reported three false survivors; the package with the test was never run. Check that the runner's package list covers the file you just mutated before believing a "survived".
- An overview assertion has to pick its width on purpose. Above `minTwoColWidth` (110) `Columns` interleaves the two blocks line by line and cuts each to its own column, so `"Tags\nnone"` never appears and a long value ends in `…`; both cost a red gate on the first try. Assert a section's WORDS below the threshold where each block is laid out whole, and keep the two-column width for what only it can show. The stacked path truncates to the pane too (it did not before this stage), so neither layout is a place where a long line survives intact.
- An assertion that cannot fail passes the gate and the eye. Two shapes both shipped in one group: comparing the code under test against the constant it came from (`*q.Period != metricPeriod` agrees with any value the constant is changed to — pin the literal), and a guard masked by an earlier one (with a nil client, an unguarded empty id still errors on the client, so `err != nil` cannot tell which guard fired — assert the message, or set up so only the guard under test can answer). Mutation finds both; reading finds neither. And a mutant that does not COMPILE is not a kill — an unused `ok`, `byID` or `cached` left behind by the edit means the compiler caught it and no test did, so write every mutant to compile and report a build failure as its own outcome.
- A fetch that moves onto a ticker has to be re-costed, not just re-called: `GetInstanceDetails` made its own `DescribeAddresses` call, so consuming it from a 2s overview silently put an account-wide lookup on a ticker. Grep a fetch for the calls it makes INSIDE it before reusing it on a refresh path, and split the ones whose frequency is a cost decision (alarms, addresses, ASG) so the caller schedules them.
- A guard that only ever ran behind another function's guard is not a guard. `DescribeInstanceAddresses` had none because `GetInstanceDetails` checked first; the moment a second caller reached it directly, a nil SDK client was a panic. When extracting or promoting a call, check what its old caller was validating on its behalf.
- An optional REQUEST field is the least testable line in a mapper and the most silent when wrong: `DescribeClusters` returns statistics and settings only when `Include` asks, and omitting it answers zero rather than an error, so the data reads as an idle cluster. Same shape as any flag that widens a response. Put the field list behind a named function (`clusterDescribeFields`) so the request is assertable, because the call itself sits behind a concrete SDK client that no test can reach.
- When a fetch derives a fact that only IT can see and something else later depends on, map and record in ONE named step. Two adjacent statements let a mutant delete the recording with the suite green, and here it was worse than that: the second call was left behind by a refactor and ran twice, which is what made the mutant look survivable. If deleting a line changes nothing that any test can see, the line is either dead or the design is wrong.
- `buildECSTask` takes its task-definition loader as a PARAMETER, so it needs no seam and can be tested with a hand-built definition — the concrete-SDK-client gap is not uniform, and it is worth checking each function's signature before recording it as untestable. Test the pairing with the sidecar listed FIRST: a mapper keyed on position instead of on name passes every same-order fixture.
