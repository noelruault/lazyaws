# Security policy

## Supported versions

Only the latest release receives security fixes.

## Reporting a vulnerability

Use GitHub private vulnerability reporting from the repository's Security tab. Do not open a public issue for a vulnerability that could expose AWS credentials, account data, secret values, or command execution.

If private reporting is unavailable, open a public issue requesting a private contact channel without including technical details, live identifiers, credentials, logs, or reproduction data from a real AWS account.

Include the affected version, operating system, impact, and the smallest reproduction that uses fabricated data. Reports involving read-only-mode bypasses, unsafe subprocess arguments, credential or session-cache exposure, and unintended disclosure to a chat backend are treated as security issues.
